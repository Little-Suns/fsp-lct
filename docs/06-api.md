# 6. Описание API

Бэкенд — FastAPI (`backend/app/main.py`, роутеры в `backend/app/routers/`). Фронт ходит в тот же API через `fetch`, отдельного приватного API у него нет: всё, что умеет интерфейс, доступно и по HTTP. Все методы — под префиксом `/api`, тела запросов и ответов — JSON (кроме загрузки файлов, PDF-профиля и потока чата).

## Спецификация OpenAPI

| Где | Что |
|---|---|
| `http://<стенд>/docs` | живой Swagger UI: методы, схемы запросов, кнопка «Try it out» |
| `http://<стенд>/openapi.json` | спецификация OpenAPI 3.1, генерируется FastAPI из кода |
| `docs/openapi.json` | та же спецификация, выгруженная из кода для приложения к документации |

Выгрузка без базы и без сервера: `cd backend && DEMO=0 uv run python -c "import json; from app.main import app; print(json.dumps(app.openapi(), ensure_ascii=False, indent=2))" > ../docs/openapi.json`. В спецификации 93 операции, заголовок «ФСП Карьера API», версия 0.1.0. В схему не входят служебные адреса: мок-провайдер ФСП ID `/mock-fsp-id/*` и страницы фронта (`/`, `/candidate…`, `/employer…`, `/v`, `/org`).

**Что в OpenAPI пока неполно.** В спецификации описаны **запросы** (тела — Pydantic-модели с типами и ограничениями, параметры пути и строки запроса), общие ответы с ошибками 401, 403, 404, 409, 413, 422, 429 и 503 (`ErrorResponse`) объявлены глобально для всех методов (`FastAPI(..., responses=…)` в `backend/app/main.py`), краткий справочник — `docs/api.md`. Модели успешных ответов (`response_model`, `backend/app/api_schemas.py`) пока есть у шести ключевых методов обратного найма: потребности (создание и список), подборка, карточка кандидата, поиск по банку и приглашение; остальные возвращают словари без схемы ответа `200`. Поэтому ниже для каждой группы методов перечислены ключевые поля ответа и специфичные ошибки, а для ключевых методов приведены примеры. Источник — код роутеров. Модели ответов в OpenAPI — ближайшая доработка (`table.md`).

Ещё одна особенность: аутентификация не объявлена в спецификации как `securityScheme`, а `Authorization` у каждого метода — обычный заголовок-параметр. В Swagger UI токен вписывается в поле `authorization` метода в виде `Bearer <токен>`; общей кнопки «Authorize» нет.

## Аутентификация

Вход выдаёт **Bearer-токен сессии**, который передаётся в заголовке `Authorization: Bearer <токен>`. Токен — 32 случайных байта (`secrets.token_urlsafe`), в базе хранится только его sha256, срок жизни — 30 дней. Новый вход отзывает прежний токен, `POST /api/auth/logout` отзывает текущий (`backend/app/deps.py`).

| Способ | Методы | Когда доступен |
|---|---|---|
| Код на почту | `POST /api/auth/email {email, role}` → письмо с 6-значным кодом (живёт 10 минут, новый — не чаще раза в минуту, 5 попыток); `POST /api/auth/verify {email, otp}` → `{token, role, has_profile}` | всегда; без SMTP вне демо — 503. Код хранится как HMAC с серверным ключом `SECRET_KEY`. Пользователь создаётся только после подтверждения почты, роль выбирает владелец адреса |
| ФСП ID (Keycloak, OpenID Connect) | `POST /api/auth/fsp/start` → провайдер → `GET /api/auth/fsp/callback` → `POST /api/auth/fsp/exchange {ticket}` → `{token, role, has_profile}` | если настроен `FSP_ID_*` или включён мок; подробно — раздел 5 |
| Демо-вход за персонажа | `POST /api/auth/demo/{role}` (`candidate` — Дмитрий Орлов, `employer` — «Ладога Пэй») | только при `DEMO=1`, иначе 404. В демо `POST /api/auth/email` ещё и возвращает код в ответе (`otp`). Общий демо-токен вне `DEMO=1` не действует |
| Токен организатора | `Authorization: Bearer <ORGANIZER_TOKEN>` | только для `POST /api/achievements/import` и `POST /api/validation/run` (вне демо); альтернатива — пользователь с ролью `admin` |

**Роли.** `candidate` (кандидат), `employer` (компания), `admin` (организатор). Роль проверяется зависимостями FastAPI: `current_user` — любой вошедший; `current_candidate` — создан профиль кандидата, иначе 403; `current_company` — зарегистрирована компания, иначе 403; `active_company` — компания не заблокирована по отзывам кандидатов, иначе 403. Кандидат видит только свои приглашения, отклики и решения: чужой объект отвечает 404, а не 403, чтобы не раскрывать, что он существует.

## Общие коды ошибок

Ошибки приходят как JSON `{"detail": …}`. Текст `detail` — по-русски и рассчитан на показ пользователю (фронт показывает его как есть).

| Код | Что значит в этом API | Формат `detail` |
|---|---|---|
| 401 | Нет токена, токен неверен или истёк («Нужен вход»); неверный или истёкший код входа; устаревший билет ФСП ID; неверный токен организатора | строка |
| 403 | Роль не та или нет профиля («Профиль кандидата не создан», «Компания не зарегистрирована»); компания заблокирована до ручной проверки; нет действующего согласия (на обработку данных — для принятия приглашения, отклика, решения задания и чата; на внешние данные — для Codeforces и CTFtime); кандидат без теста пытается откликнуться или решить задание; импорт протоколов не организатором | строка |
| 404 | Объект не найден или не виден этому пользователю. Сюда же относятся: кандидат без теста или скрывший профиль от компании («Кандидат не найден» — существование не раскрывается); демо-методы вне `DEMO=1`; нет активной сессии теста | строка или пусто |
| 409 | Конфликт состояния: приглашение уже закрыто или истекло; повторное приглашение раньше срока; ёмкость кандидата заполнена (4 открытых приглашения); ответ не на текущее задание теста; тест не завершён или уже завершён; вакансия закрыта, истекла или превышен лимит открытых; решение уже отправлено; прогон валидации уже идёт; привязка внешнего профиля изменилась во время проверки | строка |
| 413 | Тело запроса больше 6 МБ (все методы); резюме больше 5 МБ; протокол больше 2 МБ | строка |
| 422 | Ошибка входных данных. Два вида: (1) **валидация FastAPI/Pydantic** — тип, обязательное поле, длина, сумма больше 10 млн ₽: `detail` — массив `[{type, loc, msg, input, …}]` (у суммы `msg` по-русски, у остальных — стандартный английский текст Pydantic); (2) **правила домена** — значение не из справочника (специализация, трек, грейд, формат, причина отказа), неверный ИНН, неверный формат протокола: `detail` — строка с перечнем допустимых значений. У приглашения и вакансии нарушение правил (вилка, формат, справочники) — `detail = {"errors": [...], "warnings": [...]}` | массив, строка или объект |
| 429 | Лимит частоты: новый код почты раньше чем через 60 с; больше 5 проверок кода Codeforces; недельная квота приглашений компании исчерпана; больше 10 откликов кандидата за 7 дней; больше 20 сообщений чата в минуту; запуски задачи на код на примерах (не больше 20 удачных и не чаще раза в 3 с); решение уже проверяется | строка |
| 502 | Внешний сервис ответил ошибкой или недоступен: Codeforces, CTFtime, провайдер ФСП ID при `start`, SMTP при отправке кода. База при этом не меняется | строка |
| 503 | Не настроено или временно недоступно: отправка писем (`SMTP_HOST`), вход через ФСП ID, банк заданий пуст, песочница задач на код занята или недоступна (задание остаётся текущим или помечается «не засчитано»), нет файла фронта | строка |

Код 500 для ожидаемых ситуаций не используется: сбой LLM уходит в фолбэк на правила (раздел 10), сбой внешних API превращается в 502, сбой песочницы — в 503.

## Методы по группам

Обозначения в колонке «Кто»: «—» — без входа; «вход» — любой вошедший; «кандидат» — пользователь с профилем кандидата; «компания» — пользователь с зарегистрированной компанией; «компания (активная)» — то же, но компания не заблокирована; «организатор» — `ORGANIZER_TOKEN` или роль `admin`. Ошибки 401 и 403 из-за роли, общие для всех защищённых методов, в колонке «Ошибки» не повторяются.

### Интеграция с ATS (`ats`)

Ключи API выпускает компания в кабинете (Bearer-сессия работодателя). Входящий API `/api/ats/v1` авторизуется заголовком `X-Api-Key` и проверяет области доступа ключа. Подробно — раздел 11.3.

| Метод | Путь | Кто | Назначение и ключевые поля | Ошибки |
|---|---|---|---|---|
| GET | `/api/employer/api-keys` | компания | Свои ключи: `id`, `name`, `prefix`, `scopes`, `created_at`, `last_used_at`, `revoked_at` (без самого ключа) | 403 |
| POST | `/api/employer/api-keys` | компания (активная) | `{name, scopes}` → то же и `key`: полный ключ только в этом ответе. Не больше 10 активных ключей | 409, 422 |
| DELETE | `/api/employer/api-keys/{id}` | компания | Отозвать ключ | 404 |
| PUT | `/api/ats/v1/vacancies/{external_id}` | ключ, `vacancies:write` | Создать или заменить вакансию по внешнему id; тело как у `POST /api/vacancies` → вакансия, `warnings`, `external_id` | 401, 403, 409, 422 |
| POST | `/api/ats/v1/vacancies/{external_id}/close`, `/extend` | ключ, `vacancies:write` | Закрыть, продлить; закрыть можно и заблокированной компании (сужает показ), продлить нельзя | 401, 403, 404, 409 |

## Ограничения

- Схемы успешных ответов в спецификации OpenAPI есть только у шести ключевых методов (см. выше), у остальных — ближайшая доработка; общие ошибки описаны у всех.
- Аутентификация не объявлена как `securityScheme`, у каждого метода — заголовок-параметр `authorization`.
- Версия API одна (`0.1.0`), версионирования путей нет — для MVP с единственным клиентом этого достаточно.
- Лимиты частоты — только прикладные (код почты, квота, чат, отклики). Общий лимит по IP предполагается на обратном прокси перед стендом (`table.md`).
